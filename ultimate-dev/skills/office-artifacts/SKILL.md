# Office Artifacts

Create a useful, editable, source-grounded artifact with a clear audience and
purpose. Use the host's document tools when available; otherwise provide a
well-structured Markdown or data artifact and state the limitation.

## Method

1. **Classify the artifact** — memo, report, spreadsheet, presentation, PDF,
   template, or dataset; identify format, audience, and required sections.
2. **Ground the content** — collect approved sources, data provenance, period,
   currency, units, and assumptions.
3. **Design before filling** — outline, hierarchy, tables, visuals, and callouts.
4. **Create or revise** — preserve editable source where possible; keep formulas,
   citations, and data provenance traceable.
5. **Validate** — structure, calculations, links, spelling, accessibility,
   privacy, metadata, and file opening.
6. **Deliver** — include the artifact, source/assumptions, validation results,
   and a concise usage note.

## Quality gates

- Every material number has a source, unit, period, and currency where relevant.
- Tables and charts have labels, readable scales, and a takeaway.
- Slides communicate one message per slide and include speaker notes when useful.
- Spreadsheets separate inputs, formulas, and outputs; avoid hidden assumptions.
- PDFs and documents preserve headings, reading order, links, and contrast.
- Redact secrets and personal data before delivery.

## Boundaries

Do not silently overwrite the source of truth. Do not claim a file was created
or validated until the host confirms the artifact and the check output.
