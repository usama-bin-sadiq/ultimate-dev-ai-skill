# Research Skill — Learn Anything

## Purpose

Not a checklist. An **ability**. When you encounter something unknown,
this skill teaches you how to figure it out — for any domain, any technology,
any problem type.

## The Ability

```
Given an unknown topic, you can:
1. Break it into answerable sub-questions
2. Find the right sources (and know which ones to trust)
3. Extract actionable knowledge from noisy information
4. Synthesize findings into a clear recommendation
5. Know what you still don't know
```

## How to Research ANYTHING

### Step 1: Decompose the Question

Never research "how to do X." Instead:

```
"What is X?"
  → What problem does X solve?
  → What are the alternatives to X?
  → What are the prerequisites for X?
  → What are the constraints of X?
  → What are the trade-offs of X vs alternatives?
```

### Step 2: Find the Right Sources

```
Source Quality Ladder:
  1. Official documentation (authoritative)
  2. Source code (ground truth)
  3. RFCs/specifications (design intent)
  4. High-star repos (community validation)
  5. Conference talks (cutting edge)
  6. Technical blogs (practical experience)
  7. Stack Overflow (crowd wisdom)
  8. Forum posts (edge cases)
  
Source Red Flags:
  - No date visible (could be outdated)
  - No author attribution
  - Tutorial mills (content farms)
  - Single source with no corroboration
```

### Step 3: Extract Actionable Knowledge

For any technology, extract:

```
1. WHAT it is (one sentence)
2. WHY it exists (what problem it solves)
3. HOW it works (mental model)
4. WHEN to use it (decision criteria)
5. WHEN NOT to use it (anti-criteria)
6. WHAT are the alternatives (landscape)
7. WHAT are the trade-offs (cost/benefit)
8. WHAT are the gotchas (pitfalls)
```

### Step 4: Build a Mental Model

```
For any system, ask:
- What is the input?
- What is the output?
- What happens in between?
- What can go wrong?
- What are the assumptions?
- What are the edge cases?
```

### Step 5: Know What You Don't Know

```
Confidence Levels:
  HIGH   → I can teach this to someone else
  MEDIUM → I can use this but couldn't explain the internals
  LOW    → I've read about this but haven't tried it
  NONE   → I don't know this yet
```

## Universal Questions (for ANY topic)

```
1. What is it?              (definition)
2. Why does it exist?       (purpose)
3. What problem does it solve? (motivation)
4. What are the alternatives? (landscape)
5. What are the trade-offs? (evaluation)
6. How does it work?        (mechanism)
7. What are the gotchas?    (pitfalls)
8. When should I use it?    (decision)
9. When should I avoid it?  (anti-pattern)
10. How do I learn more?    (next steps)
```

## Operating Contract

- **Inputs:** a bounded question, scope, source requirements, and decision context.
- **Output:** claim/source ledger, synthesis, confidence, unknowns, and next steps.
- **Verification:** trace material claims to sources; label stale, missing, or conflicting evidence.
- **When not to use:** for a known fact with an authoritative local source, answer directly and cite it.

## Anti-Patterns

- DO NOT research without first defining the question
- DO NOT trust a single source
- DO NOT skip the "when NOT to use" analysis
- DO NOT present uncertainty as confidence
- DO NOT confuse "I read about it" with "I understand it"
