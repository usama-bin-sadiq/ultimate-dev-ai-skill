# Examples

This directory contains example tasks demonstrating how the ultimate-dev skill handles different types of work.

## Available Examples

| Example | Type | Complexity | Workflow Used |
|---------|------|------------|---------------|
| [Simple Task](./simple-task/) | Bug fix | Low | default |
| [Backend Feature](./backend-feature/) | Feature implementation | High | implementation |
| [Bug Fix](./bug-fix/) | Debugging | Medium | debugging |

## How to Use These Examples

1. Read the `README.md` in each example directory.
2. Study the task description, context, and expected output.
3. Follow the workflow steps to understand the approach.
4. Use these as templates for similar real-world tasks.

## What Each Example Demonstrates

### Simple Task
- A straightforward bug fix with clear requirements.
- Demonstrates the default workflow: detect → classify → route → execute → verify → review.
- Shows how to write a good handoff with evidence.

### Backend Feature
- Implementing a new API endpoint from scratch.
- Demonstrates the implementation workflow: spec → plan → implement → test → review.
- Shows how to handle scope, write tests, and document decisions.

### Bug Fix
- Debugging a non-obvious issue with intermittent symptoms.
- Demonstrates the debugging workflow: reproduce → hypothesize → isolate → fix → verify.
- Shows systematic troubleshooting and regression testing.

## Creating Your Own Examples

To add a new example:

1. Create a directory under `examples/` with a descriptive name.
2. Include a `README.md` with:
   - Task description
   - Context and constraints
   - Step-by-step walkthrough
   - Expected output/handoff
3. Keep examples realistic but focused on demonstrating specific workflows.
4. Include both the problem and the solution approach.
