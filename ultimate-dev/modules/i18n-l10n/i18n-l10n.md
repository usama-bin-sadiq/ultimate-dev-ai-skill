# Internationalization & Localization Module (pattern-based)

## Core Principles (technology-agnostic)

1. **Separate translatable content** — never hardcode user-facing strings
2. **Locale-aware formatting** — dates, numbers, currencies, units
3. **RTL support** — design for bidirectional text from the start
4. **Pluralization rules** — handle complex plural forms (ICU standard)
5. **Translation workflow** — human review for quality, machine for speed

## Key Patterns

### String Management
- Message catalogs (key-value extraction)
- ICU MessageFormat for complex strings
- Nested keys for namespacing
- Placeholder interpolation
- String externalization

### Locale-Aware Formatting
- Date/time formatting (locale-specific)
- Number formatting (decimals, grouping)
- Currency formatting (symbol, position)
- Unit formatting (metric vs imperial)
- Relative time formatting ("2 hours ago")

### RTL & Bidirectional
- CSS logical properties (inline/block)
- HTML dir attribute
- Bidi text handling
- Mirror icons/UI for RTL
- Mixed LTR/RTL content

### Pluralization
- ICU plural rules (one, few, many, other)
- Gender-based forms
- Select/selectordinal patterns
- Zero-form handling

### Translation Workflow
- Pseudolocalization for testing
- String extraction from code
- Translation memory
- Context descriptions for translators
- String validation (placeholders, format)

## Anti-Patterns
- Bad: "Concatenate strings for translations" — violates separate content
- Good: "Use message keys with placeholders" — satisfies separate content

- Bad: "Assume LTR layout" — violates RTL support
- Good: "Use logical CSS properties" — satisfies RTL support

## Output Contract
- Locale configuration
- Translation catalogs
- Formatting utilities
- RTL test results
- Translation workflow documentation
