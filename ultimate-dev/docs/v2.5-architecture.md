# Ultimate-Dev 2.5 Architecture

## Canonical separation

| Layer | Owns | Does not own |
|---|---|---|
| Model | reasoning, planning, interpretation | durable memory |
| Orchestrator | pattern selection and coordination | evidence truth |
| Runtime | state, execution lifecycle, checkpoints, recovery, policy, verification | domain expertise |
| Capability layer | tool actions and provider mapping | task planning |
| Evidence | observable proof | model assertions |

## Why this survives model/context changes

The task contract, state, checkpoints and handoff packets are filesystem-backed.
A new session can resume from them. Context is selected progressively rather
than copied wholesale.

## Why native host adapters matter

No arbitrary directory is treated as a universal convention. Each host receives
the same canonical skill through its own discovery mechanism. The generic
`.agents/` surface is a fallback only.

## Backward compatibility

The v2.3 agent, module, skill, router and LangChain reference catalogs remain.
The runtime is additive and can be adopted incrementally.

## Small-model strategy

Small models receive a compact task contract, current state, one relevant skill
and the minimum file set. The runtime handles durable bookkeeping so the model
does not need to remember the entire project.

## Large-model strategy

Larger models can plan broader DAGs and parallel work, but the same contracts,
checkpoints and verification gates remain. More context is an optimization, not
a correctness requirement.
